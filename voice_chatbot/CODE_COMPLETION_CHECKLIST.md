# 代码完成检查清单

本文档记录了每次代码修改完成后需要执行的标准操作步骤。请在完成代码修改后，按照此清单逐项检查。

## 1. 代码测试

### 1.1 语法检查
- [ ] 运行语法检查，确保所有修改的Python文件没有语法错误
  ```bash
  python -m py_compile voice_chatbot/修改的文件.py
  ```

### 1.2 导入测试
- [ ] 测试新模块是否可以正确导入
  ```bash
  python -c "from voice_chatbot.模块名 import 类名或函数名"
  ```

### 1.3 功能测试
- [ ] 运行相关测试脚本（如果存在）
- [ ] 手动测试新功能是否正常工作
- [ ] 测试边界情况和异常处理

## 2. 文档更新

### 2.1 DEVELOPMENT_LOG.md
- [ ] 在 `DEVELOPMENT_LOG.md` 文件开头添加新的日志条目
- [ ] 记录以下内容：
  - 实现日期和时间
  - 功能描述
  - 实现内容（核心功能列表）
  - 修改文件清单
  - 配置说明（如果有新配置项）
  - 测试结果
  - 注意事项

**格式示例**：
```markdown

   - 详细说明

#### 修改文件清单
1. `文件路径1` - 修改说明

```

### 2.2 THREAD_SCHEDULING.md（如果涉及线程或流程）

- [ ] 更新相关章节：
  - 线程描述
  - 状态转换规则
  - 关键参数配置
  - 流程说明

### 2.3 PROJECT_OUTLINE.md（如果涉及架构变更）
- [ ] 如果修改涉及模块架构或功能列表，更新 `PROJECT_OUTLINE.md`
- [ ] 更新相关模块的功能列表
- [ ] 更新注意事项或技术细节

## 3. 代码质量检查

### 3.1 代码规范
- [ ] 检查变量命名是否符合Python规范（snake_case）
- [ ] 检查函数和类是否有适当的文档字符串
- [ ] 检查是否有未使用的导入或变量

### 3.2 错误处理
- [ ] 确保关键操作都有异常处理
- [ ] 确保错误信息清晰明确
- [ ] 确保资源正确释放（文件、锁等）

### 3.3 线程安全
- [ ] 如果涉及多线程，确保共享状态使用锁保护
- [ ] 检查是否有死锁风险
- [ ] 确保daemon线程设置正确

## 4. 配置管理

### 4.1 配置项
- [ ] 如果添加了新配置项，确保在 `config.py` 的 `DEFAULT_CONFIG` 中定义
- [ ] 确保配置项有合理的默认值
- [ ] 确保配置项有清晰的注释说明

### 4.2 向后兼容
- [ ] 确保新功能不影响现有功能
- [ ] 确保配置项有默认值，不会导致旧配置失效
- [ ] 如果移除了配置项，确保有迁移说明

## 5. 事件系统（如果涉及）

### 5.1 新事件类型
- [ ] 如果添加了新事件类型，在 `events.py` 中定义
- [ ] 在 `EVENT_PRIORITY_MAP` 中设置优先级
- [ ] 在 `EVENT_CATEGORY_MAP` 中设置日志类别（如果使用EventLogger）

### 5.2 事件模板
- [ ] 在 `EVENT_MESSAGE_TEMPLATES` 中添加消息模板（如果使用EventLogger）

## 6. 提交前检查

### 6.1 最终验证
- [ ] 运行完整的语法检查
- [ ] 确认所有待办事项已完成
- [ ] 确认所有文档已更新
- [ ] 确认代码可以正常运行

### 6.2 代码审查
- [ ] 检查是否有硬编码的值应该改为配置项
- [ ] 检查是否有TODO或FIXME注释需要处理
- [ ] 检查是否有调试代码需要移除

## 7. 特殊场景

### 7.1 性能优化
- [ ] 如果涉及性能优化，记录优化前后的对比数据
- [ ] 在DEVELOPMENT_LOG.md中记录性能提升情况

### 7.2 新依赖
- [ ] 如果添加了新依赖，更新requirements.txt或相关依赖文件
- [ ] 在DEVELOPMENT_LOG.md中记录新依赖及其用途

### 7.3 破坏性变更
- [ ] 如果有破坏性变更，在DEVELOPMENT_LOG.md中明确标注
- [ ] 提供迁移指南或兼容性说明

## 使用说明

1. **每次完成代码修改后**，打开此文档
2. **逐项检查**，完成的项目打勾（✅）
3. **确保所有必填项都已完成**后再提交代码
4. **如果某项不适用**，可以跳过，但建议记录原因
